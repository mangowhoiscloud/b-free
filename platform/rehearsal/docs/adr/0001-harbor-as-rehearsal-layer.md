# 0001. Harbor(에이전트 샌드박스 · 평가 프레임워크, CNCF 레지스트리 Harbor와 다름)를 리허설 실행 계층으로 쓴다

- 상태: 제안 (11/2 21:00 회의에서 결정)
- 날짜: 2026-11-02
- 결정한 사람: 류지환 제안

## 맥락
통합 설계 문서 v0.1은 Harbor를 평가 전용(P1)으로 둡니다. 팀장은 모든 에이전트 작업이 샌드박스를 전제로 한다고 봅니다. 런타임과 평가가 다른 경로면, 발표 수치가 데모 경로를 설명하지 못합니다.

## 결정
모든 에이전트 호출을 Harbor Trial 하나로 실행합니다. 환경은 목적지 K3s의 리허설 네임스페이스이고, 커스텀 어댑터로 연결합니다.

## 검토한 대안
| 대안 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|
| Harbor 평가 전용(v0.1) | 데모 속도 영향 없음 | 런타임 격리와 채점을 직접 구현. 평가와 런타임 경로가 다름 | 전제와 맞지 않음 |
| 내장 ack backend | 코드가 가장 적음 | privileged root Pod. no-network task 거부 | 첫날 시간 측정에만 씀 |
| 세션 VM의 docker backend | Harbor 정책 집행을 그대로 씀 | 목적지 클러스터 구성에서 돌지 않음. nftables 조건 | 대안으로 남김 |

## 결과
- 쉬워지는 것: task, 분리 검증기, 궤적, 재채점, 반복 평가를 Harbor에서 받습니다.
- 어려워지는 것: 어댑터 약 370–570줄(추정)과 Harbor 버전 갱신을 직접 따라갑니다.
