# 영역 계획: 에이전트 · 리허설

스펙 §11.2의 담당 3 영역입니다. 작업은 T3, T11, T15, T16, T26입니다. 보상 조작 시험 T26a는 실행 계층과 무관하게 P0로 더합니다. D-02가 채택되면 T15a도 더해집니다. 담당 이름은 11/2 회의에서 정합니다.

## 1. 이 영역이 증명할 것

중점 ③ "AI는 격리된 리허설에서만 고치고, 별도 검증과 사람 승인 뒤에만 반영된다"입니다. 심사에서는 AI 활용(10점)과 클라우드 활용(30점) 중 권한 관리에 걸립니다. 데모 장면은 스펙 §10의 0:00–1:30입니다.

**라이브로 보일 장면.** 게이트 1차가 열린 첨부 저장소로 BLOCK합니다. 에이전트가 목적지 저장소의 버킷 정책 제안서를 냅니다(저장소 후보 Rook-Ceph RGW, 제안 D-22, 검증 중). 리허설과 검증을 거쳐 게이트 재대조가 PASS가 되고, 사람이 승인합니다. 이미지 빌드가 없어 시간 안에 들어갑니다. 차단 장면은 앱 저장소에 심은 악성 지시(프롬프트 주입)로 일으키고, 화면에 "심은 시나리오"로 표시합니다. 에이전트가 우연히 위험한 명령을 내기를 기대하지 않습니다.

## 4. 11/5 통합 인수 조건

1. 버킷 정책 Trial이 검증 네임스페이스의 비공개 테스트를 통과합니다.
2. 결과가 게이트 재대조 PASS와 승인으로 이어지고, 승인은 검증한 diff와 digest에 묶입니다.
3. no-op 에이전트는 검증에서 실패합니다.
4. 보상 조작 시험의 공격과 검증 경계 시험 V1–V6, V3b가 모두 막힙니다.
5. 심은 악성 지시가 도구 계층에서 거부되고 콘솔에 기록됩니다.

## 6. 지금 있는 것

`platform/rehearsal/`에 프로토타입이 있습니다. 4사분면 분류, 구조화한 도구 계층, 판정, task 생성기와 import 없는 검증기, Harbor 어댑터 골격, 러너가 있고 시험 35개가 통과합니다. 리뷰가 재현한 치명 결함 2건은 고쳤습니다. 실제 클러스터에는 아직 붙지 않았고, 남은 결함은 `docs/architecture/05-agent-rehearsal.md` 6절에 있습니다. 실제 목적지에서 V1–V6을 통과하기 전에는 프로토타입의 reward를 승인 근거로 쓰지 않습니다. 도구 계층은 아직 Pod, Deployment, Job의 apply를 받으며, T11에서 ConfigMap 하나로 줄입니다.
