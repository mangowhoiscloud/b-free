## 4. 담당별 직렬 부하

스펙 §11.2대로면 데이터 · 컷오버 담당이 가장 긴 경로의 T8, T12, T20과 계약 둘(T10, T12)을 같이 맡습니다. D-18–D-20이 채택되면 운영자 MCP, 인증, 효과 원장, 보류 집행까지 이 담당에게 몰립니다.

**담당 제안.**

| 일 | 제안 담당 | 이유 |
|---|---|---|
| T10(상태 머신, API), 운영자 MCP 서버(D-18), 운영자 인증(Access JWT 검증, `principals`, `authorize`) | 콘솔 · 관측 · Edge | 콘솔이 API의 첫 소비자이고, Access와 Tunnel을 이미 맡음 |
| P0 효과 원장(`effects`, `resource_locks`, `bravo_fence`, 관찰 전용 모드, E1–E6) | 데이터 · 컷오버(Executor 담당) | Executor 담당에게는 이것만 더함 |
| 첨부 복사 Job(D-04) | 새 작업 줄. 번호와 담당은 회의에서 정함 | 가장 긴 경로 밖에 둠 |

**장애 시험은 P0 완료 조건입니다.** 아래 네 가지는 해당 작업의 P0 완료 조건으로 둡니다.

| 장애 | 시험 |
|---|---|
| 응답 유실 | E1, E3(`platform/executor/README.md`) |
| 지연 명령 | E5 |
| 첨부 동결 경쟁 | D-04 인수 시험 첫 줄 |
| 보류 경쟁 | H9(`docs/architecture/04-governance.md` 5절) |

이것은 스펙에서 T25(반복 측정 · 장애 주입 · SAFE_HOLD 시험)가 P1인 것과 부딪힙니다. 회의에서 T25의 이 부분만 P0로 올릴지 정합니다.

## 5. 늦어질 때

**범위를 줄이는 순서.** 기본 데모 계약(S1–S4의 인수 조건)은 줄이지 않습니다.

1. 11/3에 운영자 MCP 읽기 도구를 실제 Claude Code 연결로 먼저 확인합니다. 11/5 18:00까지 안 붙으면 데모는 콘솔로만 합니다(D-18).
2. 자동 인계를 하지 않습니다. 미해결 효과는 관찰 전용 모드와 SAFE_HOLD, 런북으로 처리합니다(D-19, 이미 반영).
3. 에이전트는 워크로드를 만들지 않습니다. 고정 템플릿과 신뢰된 빌드만 씁니다(`docs/architecture/05-agent-rehearsal.md` 3절, 이미 반영).
4. 11/5까지 첨부 계약이 준비되지 않으면 WATCH 동안 신규 첨부를 막고 "WATCH 신규 첨부 복구 미지원"을 보입니다(D-04).
5. D-01(GCP 환경)을 P2로 내립니다.
6. D-02의 실행 계층 Harbor(에이전트 샌드박스 · 평가 프레임워크, CNCF 레지스트리 Harbor와 다름)를 스펙 방안 1로 되돌립니다.
7. P1 작업(T23, T24, T26, T27)을 뒤로 미룹니다.

**비상 대체 장면.** 아래는 무대에서 실패했을 때만 씁니다. 기본 계약을 바꾸므로, 미리 쓰기로 정하려면 편차로 올립니다.

- Cloudflare LB 대신 DNS 전환: 가중치 단계 전환(FR-8)을 하지 못합니다. 화면에 기능 축소로 보입니다.
- S2 코드 수정의 사전 실행 기록: 실행 ID와 시각을 `recorded`로 보입니다. 버킷 정책 번역은 라이브로 둡니다.
