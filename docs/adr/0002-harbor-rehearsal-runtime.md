# 0002. 리허설 실행 계층으로 Harbor를 씀

- 상태: 채택(되돌림 기준 있음)
- 날짜: 2026-11-02
- 정한 사람: 류지환(팀장) 결정, 2026-11-02 21:00 회의에서 공유
- 스펙 위치: §8.4, §12("Harbor 역할 확정"), T15, T26, D-02
- 근거 문서: `docs/spec/DEVIATIONS.md` D-02, `docs/spec/ALIGNMENT-2026-11-02.md` 3.2절, 1급 원천 [harbor-adoption.md](../spec/sources/harbor-adoption.md), `docs/architecture/07-runtime-mesh-observability.md` 3절, `platform/rehearsal/README.md`

이 문서의 Harbor는 에이전트 샌드박스 · 평가 프레임워크입니다. CNCF 레지스트리 Harbor와 다릅니다.

## 맥락

스펙 §8.4는 런타임을 직접 띄운 리허설 네임스페이스로 두고, Harbor는 평가 전용(P1)으로 둡니다. §12는 Harbor의 역할 확정을 에이전트 · 리허설 담당에게 맡깁니다. 1급 원천 「Horbor 도입 관련」은 방안 1(런타임은 직접, Harbor는 평가만)을 추천합니다.

제약은 셋입니다. 에이전트는 클러스터 자격이 없어야 합니다(NFR-4). 판정은 에이전트가 고칠 수 없는 분리 검증기가 해야 합니다(FR-5). 같은 실행 경로를 T26 평가에도 써야 측정과 데모가 같은 것을 봅니다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 스펙 방안 1: 리허설 네임스페이스를 직접 띄우고 Harbor는 평가만 | 의존이 적음. 1급 원천의 추천 | 데모 경로와 평가 경로가 갈라짐. 분리 검증 · 증거 수거를 직접 만들어야 함 |
| B. 리허설 1회 = Harbor Trial 1회(방안 2 쪽) | 분리 검증기(`environment_mode="separate"`), Trial 수명, 궤적 기록을 그대로 씀. T26과 같은 경로 | Harbor 0.25.0은 1년 미만, 릴리스 서명 없음. 보상 선기록 이슈 #2551을 우리가 막아야 함(`TECH-STACK-SPEC.md` 2.8절) |

## 결정

B를 고릅니다. Harbor 환경 어댑터가 목적지 K3s에 `rehearsal-<plan>-<n>`을 만들고, 검증기는 `verify-<plan>-<n>`에서 돕니다. 스펙 §8.4의 격리 규칙은 D-12의 예외와 함께 지킵니다. 리허설 러너 뒤에 같은 인터페이스(`start`, `exec`, `verify`, `stop`)를 두어 A로 돌아갈 길을 남깁니다.

**되돌림 기준(D-02).** 11/4 18:00까지 실제 목적지에서 다음이 한 번에 돌지 않으면 A로 돌아갑니다. 네임스페이스 생성, 에이전트 Job 기동, 도구 계층을 거친 exec와 파일 전송, Trial 취소와 종료, 증거 수거, 분리 검증, 삭제입니다.

## 결과

- 쉬워지는 것: 데모의 S2 장면과 T26 평가 수치가 같은 Trial 기록에서 나옵니다. 검증 Pod UID와 산출물 digest가 맞을 때만 PASS로 셉니다(`platform/rehearsal/README.md`).
- 어려워지는 것: Harbor 판과 배포 파일을 sha256으로 고정해야 합니다. 보상 조작 시험(T26a)이 늡니다.
- 2026-11-02 20:45 KST 상태: 실제 목적지에서 돈 Trial은 없습니다. 감사 B7(검증기가 제안 JSON 정적 검사뿐), B8(모든 역할 리허설이 INFRA_ERROR), B9(`repo_read` 루트)가 열려 있습니다(`docs/review/stub-audit-2026-11-02.md`). 되돌림 기준 판정 전에 이 셋을 고쳐야 합니다.
- 되돌리려면: 리허설 러너의 실행 경로를 A 구현으로 바꿉니다. 상태 머신, API, 도구 계층은 바뀌지 않습니다.
