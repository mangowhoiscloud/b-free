# 0001. 모노레포와 스펙 우선 규칙

- 상태: 제안
- 날짜: 2026-11-02
- 정한 사람: 전원(11/2 회의)
- 스펙 위치: §11, §12(코드 · 레포 컨벤션)

## 맥락

플랫폼은 인프라, 플랫폼 서비스 7개, 데모 앱, 부하 생성기로 나뉩니다. 다섯 영역이 동시에 개발하고, 11/7 10:00에 소스 코드 링크 하나를 제출합니다. 스펙 v0.1이 이미 요구, 작업, 계약을 정했습니다.

## 선택지

| 안 | 장점 | 단점 |
|---|---|---|
| A. 저장소 하나(모노레포) | 계약과 구현이 한 PR에서 같이 바뀜. 제출 링크 하나. 추적표 하나 | CI가 영역별 경로 필터를 가져야 함 |
| B. 영역별 저장소 | 권한과 CI가 단순 | 계약 변경이 여러 저장소에 흩어짐. 제출 링크가 여럿 |

## 결정

A를 제안합니다. 저장소 문서는 스펙을 어떻게 구현하는지만 적고, 스펙과 다르면 스펙이 이깁니다. 스펙에 없는 일은 DEVIATIONS에 제안으로 먼저 적습니다. 커밋과 PR은 `[T번호]`로 시작합니다.

## 결과

- `docs/spec/SPEC-TRACE.md`가 요구에서 폴더와 시험까지 한 번에 잇습니다.
- 스펙이 바뀌면 새 사본을 받고 추적표의 차이를 고쳐야 합니다.
- 되돌리려면 영역 폴더를 각자 저장소로 옮기면 됩니다. 폴더 사이 import가 없게 유지합니다.
