## 측정의 경계

- **부하:** 50쓰기 + 150 HTTP 읽기/s를 300초 수행했습니다. 쓰기 15,000건에서 유실·중복 0, 쓰기 p95 138.1ms·읽기 p95 123.2ms입니다. WebSocket 동시 접속 부하나 부하 중 컷오버 결과가 아닙니다. [원본](../evidence/load/README.md)
- **S2:** governance 150–210초·app_migration 180–187초 PASS는 API Pod/미리 보기 경로의 개별 실행입니다. [원본](../evidence/s2-timing/README.md)
- **SHIFT:** 실제 쓰기를 사용한 정방향 43.9초·역방향 46.8초, 단계별 오류 0. 도구 경로로 수행했으며 콘솔 계획·사람 승인 기록이 없습니다. [원본](../evidence/shift/lb-roundtrip-after-gw-fix-20261103T044632/README.md)
- **실서비스 조회:** 11:18 KST 콘솔에서 세 고객 환경과 플랫폼 서비스를 확인했습니다. 당시 계획·승인 기록은 0건이었습니다. 실제 DB 컷오버·failback의 성공 증거를 새로 만들지 않았습니다.

## Opus가 멈춘 지점

마지막 작업은 차가운 PgBouncer 풀의 예열을 확인한 뒤, 역방향 SHIFT의 10% 단계가 표본 90/100으로 실패한 지점입니다. 표본 생성 속도를 120/s로 올리는 `dd85cef`는 `pending/shift-probe-rate-120` 브랜치에 보관하며 **미배포·재시험 대기** 상태입니다. 이 공유 작업에서 그 변경을 운영 main에 합치지 않습니다.
