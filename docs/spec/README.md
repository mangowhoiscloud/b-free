# 스펙: 이 저장소의 1급 기준

이 저장소의 정본은 Notion의 **Team Bravo 본선 설계 문서 v0.1**입니다(통합 작성 배규태, 2026-11-02 04:49 공유). 11/1 회의에서 2번(김태현), 3번(배규태), 4번(류지환) 문서를 합친 판입니다.

- Notion: https://app.notion.com/p/40b8bee9ada480ecaca6f716e123368b
- 로컬 사본: `spec-v0.1-snapshot.html` (2026-11-02 04:52 판. 내용을 고치지 않습니다)
- 사본 뒤 Notion의 첨부 HTML이 2026-11-02 15:50–16:03 KST에 바뀌었습니다. 내용 비교 전입니다(`sources/spec-v0.1.md`).
- 스펙과 함께 따르는 1급 원천은 `SOURCES.md`에 등록합니다.

## 규칙

1. 스펙과 저장소 문서가 다르면 스펙이 이깁니다. 저장소 문서는 "스펙을 어떻게 구현하나"만 적습니다.
2. 코드, 문서, 이슈, 커밋은 스펙 ID를 붙입니다. 요구는 `FR-n`, `NFR-n`, 작업은 `T-n`, 시나리오는 `S1`부터 `S4`, 절은 `§8.6`처럼 씁니다.
3. 스펙에 없는 것을 하려면 `DEVIATIONS.md`에 먼저 적습니다. 상태는 "제안"으로 시작하고, 회의에서 정하면 ADR로 남깁니다.
4. 스펙이 바뀌면 사본을 새 파일로 받고(`spec-v0.2-snapshot.html`), `SPEC-TRACE.md`의 차이를 고칩니다.
5. 스펙이 정하지 않은 구현 선택(언어, 라이브러리, 판 번호, 내부 구조)은 영역 담당이 정하고 `docs/architecture/06-tech-stack.md`에 "제안"으로 적습니다. 스펙의 결정, 범위, 전이 조건, 데모 계약을 바꾸는 것만 `DEVIATIONS.md`로 갑니다.
6. 저장소 문서가 인용하는 `research/...` 경로는 저장소 밖 팀 연구 폴더입니다. 저장소 안 근거는 스펙 사본과 이 폴더의 문서입니다.
7. 팀장이 지정한 1급 원천(`SOURCES.md`)은 스펙과 함께 따르는 입력입니다. 저장소 결정이 1급 원천과 다르면 `DEVIATIONS.md`에 원천 문장을 인용해 적습니다. 정본과 1급 원천이 서로 다르면 정본을 따르고, 차이를 정렬표(`ALIGNMENT-2026-11-02.md`)에 적어 팀장에게 묻습니다. 사본과 갱신 절차는 `SOURCES.md`에 있습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `SPEC-TRACE.md` | 요구, 시나리오 인수 조건, 작업을 저장소 경로와 시험에 잇는 추적표 |
| `DEVIATIONS.md` | 스펙에 없거나 스펙과 다른 제안. 결정 전까지 구현하지 않음 |
