여기서 **모든 환경에 같은 도구를 설치하는 것은 목표가 아닙니다.** 예를 들어 IAM과 온프렘 RBAC는 구현이 달라도, “이 앱이 다른 앱의 비밀을 읽지 못하는가”라는 공통 요구와 거부 시험으로 비교합니다. 기능이 대응되지 않으면 차이를 숨기지 않고 이전을 제한합니다.

독창성 포인트

- **보안·운영 차이 지도**

  목적지에서 빠지는 권한 통제·암호화·감사·백업·AI 데이터 위치 조건을 표시하고, 각각을 `충족 / 보완 필요 / 대체 불가 / 미검증`으로 판정합니다.

- **차이를 해소하는 AI 샌드박스 루프**

  AI가 발견한 차이에 맞춰 코드·설정 변경을 제안하고 시험합니다. AI는 자신이 수정한 테스트나 정책만으로 통과를 선언할 수 없으며, 독립 검증 결과가 운영 반영을 결정합니다.

- **출발지 의존 차단 리허설**

  목적지 검증 환경에서 출발지 접근을 차단해 숨은 의존성을 확인합니다. 실패하면 의존성 지도와 이전 계획을 갱신합니다. 이 결과로 ‘앱 전환 완료’와 ‘출발 환경 없이 운영 가능’을 구분합니다.
