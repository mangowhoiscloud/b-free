## 설계 원칙

> 결정적 워크플로우(코드)가 흐름을 쥐고, 비결정적 판단(에이전트)은 정해진 지점에서만 한다. → "에이전트를 믿는 게 아니라 결과를 검증한다."

한 문장으로: **에이전트는 '제안서'만 내고, 실행과 판정은 파이프라인이 한다.**

## 1. 단계별 역할 분담

| 단계 | 결정적 워크플로우 (코드·규칙·도구) | 비결정적 판단 (에이전트) |
| --- | --- | --- |
| ① 수집 | 클라우드 API, Terraform state, DB 스키마에서 사실을 모음 | 하지 않음 |
| ② 의존성 분석 | 코드에서 클라우드 SDK import를 정적으로 탐지 | 애매한 결합을 판단해 3등급으로 분류, 이유 설명 |
| ③ 번역 | Helm·Terraform 템플릿으로 형태 고정 | IAM → RBAC·Vault 정책 같은 값과 매핑만 제안 |
| ④ 검증 | 원본 대조 게이트, 정책 린트, 샌드박스 스모크 테스트 | 실패하면 원인을 추정하고 수정안 제시 |
| ⑤ 승인 | 사람 승인 단계 (필수) | 승인자가 읽을 요약 작성 |
| ⑥ 실행 | 컷오버, 롤백 (Argo·Helm 등) | **관여하지 않음** |
| ⑦ 사후 | 지표가 임계치를 넘으면 롤백 | 로그 해석, 사후 리포트 작성 |

에이전트는 판단만 하고 ⑥ 실행에는 아예 등장하지 않는다 → Replit·Antigravity 같은 사고가 구조적으로 불가능.

## 2. 파이프라인 = 상태 머신

```text
수집 → 분석 → 제안 → 샌드박스 적용 → 원본 대조 → 승인 → 컷오버 → 사후 감시 → 완료
                ↑                    │ 실패
                └── 수정안 (최대 3회) ──┘
                       초과 시 → '사람 확인 필요'
사후 감시 중 임계치 초과 → 롤백
```

- 다음 단계로 넘어가는 조건은 코드에 고정 → 에이전트가 단계를 건너뛸 수 없음
- 상태와 전이를 그대로 화면에 표시 → 데모의 진행 상황 시각화로 재사용

## 3. 에이전트와 파이프라인 사이의 계약

에이전트는 자유 문장이 아니라 **정해진 형식의 제안서**만 낸다. 예: 번역 제안

```json
{
  "step": "translate",
  "source": { "type": "aws_iam_policy", "id": "chat-app-role" },
  "target": { "type": "minio_policy", "name": "chat-attachments-read" },
  "proposal": { "actions": ["s3:GetObject"], "resources": ["chat-attachments/*"] },
  "rationale": "S3 GetObject 권한을 MinIO 버킷 정책으로 대응",
  "risk": "low"
}
```

제안서가 거치는 순서: ① 스키마 검증(형식이 틀리면 즉시 반려) → ② 정책 린트(와일드카드 권한 등 금지 패턴) → ③ 샌드박스 적용 → ④ 원본 대조 게이트

## 4. 가드레일 구현

| 규칙 | 구현 방법 | 막는 사고 |
| --- | --- | --- |
| 출력은 스키마로만 | Pydantic·JSON Schema로 검증, 실패 시 반려 | 자유 문장 지시가 그대로 실행되는 것 |
| 실행 권한 없음 | 원본은 읽기 전용 자격증명, 쓰기는 샌드박스 네임스페이스만. 운영 kubeconfig·DB 계정은 아예 발급하지 않음 | Replit (운영 DB 삭제) |
| 파괴적 명령 차단 | 프롬프트가 아니라 **도구 계층**에서 차단 목록 적용 (rm -rf, DROP, TRUNCATE, terraform destroy, kubectl delete namespace 등) | Antigravity, Amazon Q |
| 재시도 상한 | 단계별 최대 3회, 초과 시 '사람 확인 필요' 상태로 전환 | 예선 때 CI 에이전트 40분 타임아웃 |
| 판정·실행에 LLM 금지 | 게이트·컷오버 모듈은 LLM 클라이언트를 불러오지 않도록 모듈 경계로 분리 | 같은 입력에 다른 판정 |
| 전부 기록 | 실행 ID별로 에이전트 입력·출력·검증 결과 저장 → 리플레이 (Harbor 연계) | 사후 원인 분석 불가 |

## 5. 기존 도구 활용 및 제작

- **결정적 뼈대**: Terraform·Helm(형태 고정), Argo CD/Rollouts(실행·롤백), PgBouncer + PG 논리 복제(데이터 이전).
- **에이전트**: Agent SDK + 도구 화이트리스트
- **샌드박스·평가**: Harbor
- **직접 만드는 부분**: 상태 머신, 에이전트 제안서 스키마, **원본 대조 게이트**
