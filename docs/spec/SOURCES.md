# 스펙 원천 등록부

스펙 v0.1과 함께 이 저장소를 묶는 Notion 문서를 등록합니다. 팀장이 지정한 1급 원천은 저장소에 사본을 두고, 사본마다 Notion 마지막 수정 시각과 본문 sha256을 적습니다. 처음 등록 2026-11-02 19:21 KST. Notion은 읽기만 했습니다.

## 1. 규칙

1. **정본.** 스펙 v0.1입니다. 스펙과 저장소 문서가 다르면 스펙이 이깁니다(`README.md` 규칙 1).
2. **1급 원천은 스펙과 함께 따르는 입력입니다.** 저장소 문서와 코드는 1급 원천을 스펙처럼 따릅니다. 1급 원천은 저장소 문서보다 앞섭니다.
3. **저장소 결정이 1급 원천과 다르면 `DEVIATIONS.md`에 적습니다.** 원천의 해당 문장을 따옴표로 인용하고, 사본 파일과 줄을 적습니다. 상태는 "제안"으로 시작하고, 팀장이 정하면 "결정"으로 바꿉니다.
4. **정본과 1급 원천이 서로 다르면 정본을 따릅니다.** 차이는 정렬표(`ALIGNMENT-2026-11-02.md`)에 적고 팀장에게 묻습니다. 팀장이 원천 쪽을 고르면 그 결정을 `DEVIATIONS.md`에 적습니다.
5. **후보는 입력이 아닙니다.** 팀장이 1급으로 올리기 전에는 근거로 인용만 하고, 사본을 두지 않습니다.
6. **사본은 고치지 않습니다.** 원문이 바뀌면 3절의 절차로 다시 받습니다. 스펙 사본(`spec-*-snapshot.html`)은 새 파일로 받습니다.
7. **개인 정보를 옮기지 않습니다.** 팀원의 학교, 거주지, 연락처가 원문에 있으면 지우고 그 자리에 "개인 정보 생략"을 적습니다.

## 3. 갱신 절차

1. Notion MCP `fetch`로 등록된 페이지를 다시 읽습니다. 쓰기, 댓글, 이동은 하지 않습니다.
2. `page_last_edited_at`을 등록부의 "마지막 수정"과 비교합니다. 같으면 "가져온 시각"만 고칩니다.
3. 다르면 같은 변환 규칙(표는 Markdown 표, 그림은 Notion 파일 이름만, 댓글 표시는 지움, 멘션은 링크)으로 사본의 `<!-- body -->` 아래를 바꿉니다. 개인 정보가 있으면 1절 규칙 7을 따릅니다.
4. 본문 sha256을 다시 계산해 머리말에 적습니다.

   ```sh
   sed '1,/^<!-- body -->$/d' docs/spec/sources/<파일>.md | shasum -a 256
   ```

5. 아래 4절에 한 줄을 더합니다(날짜, 파일, 옛 해시 앞 12자, 새 해시 앞 12자, 바뀐 절 요약). 바뀐 줄은 `git diff`로 봅니다.
6. 바뀐 절이 정렬표나 `DEVIATIONS.md`의 행에 걸리면 그 행을 다시 판정합니다.
7. 정본(스펙)은 본문이 첨부 HTML입니다. `get-version-changes`로 첨부 교체를 확인하고, 첨부를 내려받는 일과 새 사본을 만드는 일은 사람 승인 뒤에 합니다(`AGENTS.md`). 기존 사본은 고치지 않고 새 파일로 둡니다.

해시는 저장소 사본이 받은 뒤 바뀌지 않았는지 확인하는 데 씁니다. 원문이 바뀌었는지는 2단계의 마지막 수정 시각으로 판단합니다. 같은 원문을 다시 변환하면 공백이 달라 해시가 바뀔 수 있기 때문입니다.
