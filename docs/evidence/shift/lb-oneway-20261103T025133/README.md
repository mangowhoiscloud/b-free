# LB 편도 전환 실측(B04, B14): 2026-11-03 02:51–03:10 KST

Cloudflare LB `b-free-chat.mangowhois.ai`에서 SHIFT 단계 판정(계약 15 §10.4)을 실제로 돌렸습니다. 보유 규칙(목적지 표본 100건 이상, 보유 5초 이상 30초 이하)으로 목적지가 빨리 답하면 편도는 30.4초와 37.2초였습니다. 실제 채팅 쓰기로 판정하면 목적지 전환은 10% 단계에서 매번 0%로 돌아갔습니다(FAIL). 목적지 앱의 쓰기 한 건이 1.7–2.6초 걸리기 때문입니다. 측정을 마친 뒤 LB는 출발지 100%입니다.

## 어떻게 돌렸나

- 이미지 핀은 아직 올라가지 않았습니다(리드가 push). 그래서 커밋 `9253b8b`의 `platform/executor/src/bravo_executor`와 이 폴더의 `scripts/`를 executor-0(`bravo-platform-rke2`, `bravo-control`)의 `/tmp/shift-src`에 복사하고 `PYTHONPATH=/tmp/shift-src`로 그 Pod 안에서 돌렸습니다. 02:59 이후 실행은 표본 설정 수정(쓰기마다 다른 쿼리, 시간 제한 10초, 연결 유지)을 더한 같은 코드입니다.
- 경로는 도구 실행(계약 15 §10.9)입니다. 계획과 승인이 없고, `runs`(kind `shift`), `run_stages`, `effects`는 플랫폼 DB에 그대로 남습니다. Cloudflare 토큰은 Pod에 전달된 파일에서만 읽었습니다.
- `run-*.json`은 배포된 executor-0의 `GET /v1/runs/<run_id>` 응답입니다. `summary.jsonl`은 그 요약입니다.

```bash
kubectl --context bravo-platform-rke2 -n bravo-control exec executor-0 -c executor -- \
  sh -c 'cd /tmp/shift-src && PYTHONPATH=/tmp/shift-src python measure_shift.py dst final-to-dst'
kubectl ... -- sh -c 'cd /tmp/shift-src && PYTHONPATH=/tmp/shift-src python move_front.py src'   # LB를 출발지로(되돌리기 8단계 코드)
```

## 읽는 법

1. **보유 규칙은 60초 안에 듭니다.** 목적지가 빨리 답한 두 실험에서 편도가 30.4초, 37.2초였습니다. 이전 기준(단계마다 60초)의 편도는 184.8초였습니다.
2. **실제 쓰기로는 목적지 전환이 통과하지 못했습니다.** 목적지 앱의 쓰기는 목적지 PgBouncer와 링크를 거쳐 출발지 DB에 갑니다. LB를 거치지 않고 차례로 보낸 쓰기 8건이 02:56에 2,095–2,454 ms, 다른 부하가 없던 03:10에 1,710–2,633 ms였습니다(`direct-writes-after.json`). 출발지는 98–415 ms였습니다. 판정은 1a대로 목적지를 0%로 돌렸습니다.
3. **원인 미확인.** 목적지 쓰기가 느릴 때 Cloudflare는 10% 가중치에서도 POST를 목적지로 0.6–2.2%만 보냈습니다. 앱 카운터 `chat_writes_total`(플랫폼 Prometheus)도 같은 수입니다(`app-write-counters.jsonl`: 02:51 실행 동안 출발지 +1,791, 목적지 +10). 같은 pool로 가는 GET은 가중치를 따랐습니다(8.3%, 13.9%). LB 설정은 `random`, 세션 고정 없음, 두 pool 모두 건강(`lb-settings.json`)입니다.
4. **출발지로 돌아가는 판정의 한계.** 목적지가 느린 상태에서 출발지 10% 단계는 표본 대부분이 목적지라 판정을 통과하지 못했고, 1a 규칙대로 출발지를 0%로 두어 LB가 목적지 100%로 남았습니다(02:58, 02:59). 그래서 LB는 `move_front.py`(되돌리기 8단계와 같은 코드, 복귀 없음)로 출발지에 옮겼습니다.
5. **다른 갈래와 겹침.** 부하 생성기(B15)가 02:56부터 300초 동안 `b-free-chat-src`에, 03:01:23부터 60초 동안 `b-free-chat-dst`에 LB를 거치지 않고 초당 50건을 썼습니다(`docs/evidence/load/`). 그래서 02:58–02:59 실행의 출발지 p95(3,531 ms)와 03:02:40 실행의 목적지 오류는 그 부하의 영향을 받았고 판단에 쓰지 않습니다. 제 LB 이동은 그 부하에 닿지 않았습니다(대표 이름을 쓰지 않음).
